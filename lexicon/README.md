# 词库源 · 格式约定

> 这是**唯一真源**。改词只改这里，然后跑 `python scripts/render_lexicon.py`
> 生成 `assets/terms.json` 与 `references/07-term-library.md`。
> ⛔ 不要直接改产物。

## 一、四层结构

| 层 | 怎么写 | 举例 |
|---|---|---|
| **域** | 文件名 + `#` 标题 | `通用-风格` / `人像` / `风景自然` |
| **维度** | `##` 标题 | `材料与形式` / `风格与流派` / `参照物` |
| **要素** | `###` 标题 | `媒介与画种` / `艺术流派` / `艺术家` |
| **词条** | 一行 | `中文 ｜ 英文 ｜ 状态 ｜ 备注` |

> 域内要素 ≤ 8 个时可以省掉维度层，直接写 `###`。

**维度的切法**：问「这一格回答的是什么问题」。
- 材料与形式 → 这张图**是什么**做出来的
- 风格与流派 → 是什么**味道**
- 参照物 → 照着**谁**做

## 二、词条格式

```
中文 | 英文 | 状态 | 备注
```

- **中文** —— 词名。用中文，不夹英文。
- **英文** —— 对照检索用（艺术家名、品牌名尤其需要）。
  ⚠️ 英文只作对照，**输出提示词一律只用中文**。
- **状态** —— 一律必填，四档：
  | 状态 | 含义 |
  |---|---|
  | `常用` | 大多数场景适用 |
  | `可用` | 有效，但有明确适用场景 |
  | `少见` | 冷门，只在特定风格下用 |
  | `慎用` | **有副作用**，备注里必须写清原因 |
- **备注** —— 可空。只写两件事：**什么时候用**、**有什么坑**。
  ⛔ 不写「质量要求」（如「要画得精致」）—— 那类话对模型无效甚至反效果。

## 三、四条纪律

1. **一个词只出现一次。** 跨域、跨格都不重复 —— 这是人工源最大的好处，别破坏它。
2. **按「这个词管哪一层」归位，⛔ 不按字面归位。**
   反例：`手杖` 因为带「手」字被放进「手饰」；`副岛成记` 因为带「岛」字被放进「自然景观」；
   `分析性绘图` 因为带「绘图」被放进「媒介与画种」。
3. **⛔ 不收拼接词。** 两个词拼出来的（`水彩儿童插画` = 水彩 + 儿童插画、
   `野兽派线条` = 野兽派 + 线条）不是词条，用组合查询即可。
4. **⛔ 不收平台限定词与个人标识。** 词库随公开仓库发布，除署名外不留个人痕迹。
   把通用排版技巧绑上某个平台名（`[平台名]封面`）→ 改成中性的 `自媒体封面`：
   词条本身是通用知识，绑上平台名就变成了个人履历。
   此条有护栏：`check_terms.py` 的「脱敏护栏」断言会拦。
   ⚠️ 个人标识词表**不进仓库**（写死在代码里 = 随仓库公开），放
   `scripts/.privacy-words.txt`（已 gitignore，格式见同目录 `.privacy-words.example.txt`）。

## 四、改完必做（三条命令，缺一不可）

```bash
python scripts/render_lexicon.py           # 渲染：lexicon/*.md → 两份产物
python scripts/render_lexicon.py --check   # 只体检源，不写盘
python scripts/check_terms.py              # 校验：退出码 0 才算改完
```

⭐ `check_terms.py` 的核心断言是**一致性**，专门防「改了源忘重跑、拿旧产物交付」
和「改了标题忘改引用」这两类**不报错的失败**。
