# ai-image-prompt — AI 生图提示词共创助手

把脑子里的碎片想法（哪怕只有「一男一女，朦胧感」这五个字），通过**最多四轮对话**收敛成一条能直接出图的高质量提示词。

作者：**AI绘梦师葉子**

---

## 它解决什么问题

写生图提示词，难的从来不是"不会写"，而是这几件事：

| 常见翻车 | 本 skill 的对策 |
|---|---|
| 图出来了人小、看不清脸 —— 方向从一开始就跑偏 | **人物图第一个问题永远是「人在画面里多大」**，比画幅、风格、光线都更早定 |
| 双人图总像影楼合影，说不上哪不对 | **两个人以上必问「动作骨架」** —— 身体的关系 / 视线落点 / 焦平面分层，一件都不在五官上 |
| 说了「朦胧感 / 高级感」，AI 自己想当然翻译成一种做法 | **感受词先让用户选实现路径**再翻译 —— 选错路径 = 整张图的画面类型变了 |
| 说「做个咖啡海报」，AI 反问「你想画什么风格」 | **「XX海报 / XX风格」的主体层是空的** —— 给 2~3 个打包好的成型方案让他点，别问开放问题 |
| 提示词越写越长，四五百字还是不好看 | 真正的原因是**替你拍了板**：一堆你没要过的元素。分「中性默认」和「剧情化设定」两档处理 |
| 说「人物设定」，出来的是单张立绘或只有三个视图 | **「人物设定」默认出四视图** —— 左起第一格面部特写，右边三格正 / 侧 / 背全身立绘，16:9 四格横排 |
| 三视图出了戏剧性光影，看不清结构 | **技术图 / 人物设定 / 建筑 / 绘画形式类要整套反写** —— 均匀平光替代打脸光，墨色层次替代光位 |
| 图不对，就整条重写，越改越乱 | **从症状进，只改那一槽**；同一个方向改到第 3 版还没动 → 卡的是结构不是措辞 |
| 光在光学上挑不出错，但整张图不好看 | 拆成**两道独立的关**：光对不对 ／ 图值不值得看。第二关有可执行的判据 |

## 核心设计（几条硬纪律）

- **默认动作是「问」，不是「出词」** —— 除非用户说「你定 / 直接出」，否则至少走一轮确认
- **「人物设定 / 角色设定」默认出四视图** —— 左脸特写 + 正 / 侧 / 背三个全身，16:9 四格横排、均匀平光、纯色背景。这是唯一**不需要问「人多大」**的类型（排布本身已经把答案定死了）
- **主体 > 氛围** —— 默认不给剪影、不给背影、不给「望向远方」，那是一次偷换（把"人的美"换成"风景的美"）
- **双人像的美感不在光上** —— 「并肩站着 + 都看镜头」= 影楼合影的构图语言，光再好也只是"曝光正确的合影"
- **人物图默认光位是「打脸光」**，不是逆光；逆光只镶边不打脸 = 主体不美
- **别默认把图压暗** —— 「朦胧 / 高级 / 氛围」≠ 要暗；影调（明暗）和色温（冷暖）必须分开定
- **「亮」和「美」是两个独立的轴** —— 治暗要在曝光上改，⛔ 不许用均匀光把脸上的明暗结构抹掉
- **光对了 ≠ 好看** —— 过第一关不会自动过第二关，第二关有构图六条判据
- **人像要「真」≠ 人像要「丑」** —— 默认走美，不主动加法令纹和不对称；塑料感的三个真正成因都不是"缺瑕疵"
- **名词自带的语义压得过任何形容词** —— 「光源在她正前方、和脸一样高」那个位置其实是镜头，模型会把光挪到身后
- **⛔ 画质词一个都不加** —— `masterpiece` / `8K` / `超高清` 不是"无效"，是**有害**（会推向图库广告感）
- **⛔ 排除项一律正向化** —— 写 `不要紫色渐变` 反而把紫色渐变召唤进来；要写成「画面里只有[主体]」
- **输出只有中文一种形态** —— 不按模型分形态、不做中英双语

## 安装

把整个 `ai-image-prompt` 文件夹放进 skills 目录即可：

| 范围 | 放哪 |
|---|---|
| 个人级（所有项目可用） | `~/.workbuddy/skills/ai-image-prompt/` |
| 项目级（仅当前项目） | `<你的项目>/.workbuddy/skills/ai-image-prompt/` |

Windows 上就是 `C:\Users\<你的用户名>\.workbuddy\skills\ai-image-prompt\`。

放好后，跟带 Skill 机制的 AI 助手（WorkBuddy 等）说「帮我写个生图提示词」「画一张…」「这张图哪里不对」就会自动触发。

## 词库（1952 条）

**唯一真源是 `lexicon/*.md`** —— 人工逐条维护，12 个域一个文件。

### 四层结构

| 层 | 怎么写 | 举例 |
|---|---|---|
| **域** | 文件名 + `#` 标题 | `通用-风格` / `人像` |
| **维度** | `##` 标题 | `材料与形式` / `风格与流派` / `参照物` |
| **要素** | `###` 标题 | `媒介与画种` / `艺术流派` / `艺术家` |
| **词条** | 一行 `中文 ｜ 英文 ｜ 状态 ｜ 备注` | `手杖 ｜ cane ｜ 常用 ｜` |

维度按「这一格回答的是什么问题」来切：
**材料与形式**（是什么做的）/ **风格与流派**（什么味道）/ **参照物**（照着谁做）。

### 域一览

| 层 | 域 | 条数 |
|---|---|---|
| **通用层**（跨题材）| 通用-风格 | 294 |
| | 通用-镜头构图 | 172 |
| | 通用-色彩材质 | 163 |
| | 通用-光线 | 115 |
| | 通用-背景收尾 | 21 |
| **题材层** | 人像 | 774 |
| | 风景自然 | 108 |
| | 建筑空间 | 91 |
| | 产品静物 | 58 |
| | 文字平面 | 56 |
| | 抽象概念 | 54 |
| | 食物饮品 | 46 |

合计 **1952 条 / 12 域 / 40 维度 / 130 要素**。

### 状态四档（每个词条必填）

| 状态 | 含义 |
|---|---|
| `常用` | 大多数场景适用 |
| `可用` | 有效，但有明确适用场景 |
| `少见` | 冷门，只在特定风格下用 |
| `慎用` | **有副作用**，备注里写明原因（版权期 / 在世创作者禁指名 / 实测零效果 / 烂大街模因）|

**检索时「慎用」自动折叠并附原因**，加 `--all` 才展开。

### 三条纪律

1. **一个词只出现一次** —— 跨域跨格都不重复。
2. **按「这个词管哪一层」归位，⛔ 不按字面归位。**
   （`手杖` 进「手持道具」不进「手饰」；人名进「艺术家」不进「自然景观」）
3. **⛔ 不收拼接词** —— `水彩儿童插画` = 水彩 + 儿童插画，用组合查询即可。

### 查词用脚本，不要读文件

```bash
python scripts/lookup.py --list                  # 看四层骨架（域 / 维度 / 要素 + 状态分布）
python scripts/lookup.py --domain 人像           # 只看某个域的骨架
python scripts/lookup.py --group 天气            # 列某一格全部候选
python scripts/lookup.py --group 关系互动        # 双人图动作骨架的直接词源
python scripts/lookup.py --group 艺术家 --all    # 默认折叠慎用词，--all 展开
python scripts/lookup.py --kw 逆光               # 按中英关键词模糊查
python scripts/lookup.py --status 常用 --domain 人像   # 按状态过滤
```

## 词库维护

**改词只改 `lexicon/` 下的源文件，然后跑渲染器。**

```bash
python scripts/render_lexicon.py            # lexicon/*.md → assets/terms.json + references/07-term-library.md
python scripts/render_lexicon.py --check    # 只体检源，不写盘
python scripts/check_terms.py               # 校验：退出码 0 才算改完
```

`assets/terms.json` 和 `references/07-term-library.md` 都是**脚本生成的产物，不要手改**（重跑会覆盖）。
渲染器 `render_lexicon.py` **只做格式转换** —— ⛔ 它里面没有任何"改词"规则。

### ⛔ 为什么没有"批量规则表"了

早期版本用一个 4000 行的 `build_terms.py` 从两个源合成词库，里面写了 18 张正则规则表
（改错字 / 删词 / 同义词归一 / 优先级去重 / 归类重映射 …）。

2026-09 起词库改为**人工逐条维护** —— 那 18 张表解决的问题（错配英文、错位归类、
拼接词、同义词）现在在**写源的时候就已经解决了**。规则表留着只会造成两个恶果：
**改了源却不生效**、**规则和源互相打架**。所以它们全部退役。

### 校验的核心不是"格式合法"，是"一致性"

`check_terms.py` 现在管三类一致性，一共 14 项断言：

| 管什么 | 断言 | 防的是哪类失败 |
|---|---|---|
| **产物与源** | 条数一致 / 无幽灵词 / 对照表条数一致 | 改了源忘重跑，拿旧产物交付 |
| **文档之间** | 跨文件按标题引用能落到真实标题上 | 改了标题忘改引用（**不报错的失效**）|
| **对外** | 脱敏护栏（平台限定词 / 个人标识）、敏感词回归 | 开源时把个人痕迹带出去 |

这不是多余的小心：本项目历史上出过三次同型事故 ——
**「存在」不等于「正确」，校验维度漏了等于没校验。**

⭐ **两条新断言做过负向测试**：人为把引用改成不存在的标题、把词条绑上平台名，
退出码都立刻变 1；恢复后回到 0。没验证过会红的断言不算护栏。

> ⚠️ 脱敏护栏的**个人标识词表不在仓库里** —— 把要藏的词写死在代码里，
> 等于随仓库一起公开。要拦自己的署名 / 账号名 / 真名，写进
> `scripts/.privacy-words.txt`（已 gitignore，格式见同目录 `.privacy-words.example.txt`）。

改完跑 `check_terms.py`，退出码 0 才算完。

## 输出形态：只有中文一种

**输出统一是中文整段自然语言句，没有第二种形态。**

⛔ 不按模型分形态（没有 Midjourney 参数尾、没有 SD 正负向框）、不做中英双语版。

理由：现在的生图模型（GPT-Image、即梦、豆包、通义、Nano Banana、Seedream、可灵…）
都已经能吃通用汉字描述，**生成大部分文字也没问题**。
分形态不是"更专业"，而是把老工具的限制当成了规范 —— 还会带来一个副产物：
用户拿到一条提示词，换一个工具就不能用了。

⭐ 需要查某个词的英文时用 `scripts/lookup.py` —— 那是**检索与对照**用途，不是输出形态。

配套的两条写法纪律：

- **⛔ 画质词一个都不加** —— `masterpiece` / `8K` / `超高清` / `stunning` 不是"无效"，是**有害**（见 `05`）
- **⛔ 排除项一律正向化** —— 不写「不要 X」，写成「画面里只有[主体]」（见 `04`）
