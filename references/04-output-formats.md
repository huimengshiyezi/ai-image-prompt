# 04 · 输出形态

**只有一种形态：中文整段自然语言句。**

⭐ 2026-09 起本项目**不再按模型分形态**。原因：现在的生图模型（GPT-Image / 即梦 / 豆包 /
通义 / Nano Banana / Seedream / 可灵 / 混元…）都已经能吃通用汉字描述，
**参数尾、逗号词组链、英文负向框**那些写法不是"更专业"，而是把老工具的限制当成了规范。
分形态还会带来一个副产物：用户拿到一条提示词，换一个工具就不能用了。

⛔ 因此本文件**没有** Midjourney 附录、**没有** SD/ComfyUI 附录、**没有**英文双语版。
需要中英对照时，用 `scripts/lookup.py` 查单词，那是**检索用**的，不是输出形态。

---

## 主形态：中文整段句

适用于现阶段全部主流模型 —— 写成清楚的汉字句子，谁都能读。

### 九条硬规则

1. **⛔ 意图打头 —— 第一句写"这是什么图、干什么用"，不是主体。**
   官方（OpenAI Cookbook）给出的顺序是
   **意图 → 场景 → 主体 → 关键细节 → 文字 → 风格 → 约束**。
   开头写 `为自媒体封面做的一张 3:4 竖幅人像照片` 或 `一张电影感的双人特写照片`，
   而不是直接 `一个年轻女性`。
   ⭐ 两个独立来源都说这是**提升最大的单点改动** —— 开头的词会选中模型的"模式"。
   中文同理：先给"这是什么"，再给"里面有什么"。
2. **写句子，不写词组。** `一个年轻女性站在雨夜的巷口，霓虹灯从她右后方照过来`
   ⛔ 不是 `年轻女性, 雨夜, 巷口, 霓虹, 逆光`
3. **按 01 的装配顺序排**
   （意图 → 画幅景别 → 场景 → 主体 → **关系（双人）** → 光色材质 → 文字 → 收尾）。
   **前面的句子会盖过后面的** —— 顺序错了信息就丢。
4. **一段一槽，用句号断开。** 不要写成一大坨逗号长句，模型会丢掉后半段的约束。
5. **每个槽都要落到具体物象。** ⛔ "氛围感 / 高级感 / 唯美 / 意境" 这类词零效果，
   它们不指向任何可画的东西，只会挤占字数预算。
6. **⛔ 一个槽只写一句。** 同槽内出现"而且""另外""同时还" → 删掉后半句。
   光照槽写三句，模型只会记住第一句，后两句是纯噪声。
7. **按 Detail Mode 决定详略，不要一律写满**（见下面一节）。
8. **排除项一律正向化**（见下面一节）—— ⛔ 不写"不要 XX"，要写"画面里是什么，别的什么都没有"。
9. **收尾只写「输出规格」类约束，⛔ 不写身体部位的质量要求。**
   规格类 = 有几个主体、有没有文字水印 —— 这是**全局属性**，写一次就管用：
   `画面里只有[主体]，没有文字和水印。`（环境图去掉"浅景深"）
   ⛔ **不要写"双手五指完整""五官端正""比例协调"这类质量要求** —— 见下面一节。
   ⭐ **例外：多格图（人物设定四视图 / 表情表）** —— 不能写"只有一个主体"，
   要写成 **`四格画的都是同一个角色，画面里没有其他人`**，否则模型会画成四个人。

### ⛔⛔ 用户明确说过的「硬信息」一个字都不能丢

**这是「减法错」，和「不要自己加戏」（加法错）是一对，两头都要防。**

⛔ 漏写的危害不比乱写小 —— 而且**更难发现**，因为提示词看起来更精简了，
反而像是精简纪律执行得好。用户得等出图才知道。

**最容易丢的一类是「身份」** —— 因为中文的 `两个人` / `对方` / `旁边的人` / `他` / `她`
**都不携带身份信息**，你不写清楚，模型就按先验自己补：

> 用户说「一男一女」，你抽成"两个人"，
> 后面一路写"两个人""右边这个""左边的人" —— **模型按先验补出来的是两个男性。**

**必须落地的硬信息清单**（用户说了就一个字都不能丢）：

| 类别 | 例子 |
|---|---|
| **性别** | 一男一女 ／ 两个女性 ／ 一对父子 |
| **人数** | 三个人 ／ 只有一个人（★「只有」也是硬信息）|
| **年龄段** | 老人 ／ 孩童 ／ 少年 ／ 中年 |
| **种族 / 国籍** | 欧美面孔 ／ 亚洲面孔 ／ 混血 |
| **物种 / 形态** | 人 ／ 拟人化动物 ／ 机械体 |
| **关系** | 恋人 ／ 母女 ／ 兄弟 ／ 陌生人 |

#### 写法：身份要落到每个人的身上，不能只在开头宣告一次

| ⛔ 信息已丢 | ✅ 身份写实 |
|---|---|
| `两个人坐在长椅上` | `一名年轻女性和一名年轻男性并排坐在长椅上` |
| `右边这个正看着左边的人笑` | `坐在右边的女性正看着她身边的男性笑` |
| `两个人穿的都是深色上衣` | `她穿深色针织衫，他穿深色衬衫` |

⛔⛔ **只在第一句写"一男一女"，后面全用"两个人" → 信息依然会漂。**
这和色温 / 影调是同一条道理：**信息要落到具体的句子里，不能只宣告一次。**

⭐ **出词前逐个指代词过一遍**：把每个"两个人 / 对方 / 旁边的人 / 他 / 她"
换成本来的身份，看信息还在不在。

### ⛔⛔ 收尾句不要写身体部位的「质量要求」

**早期版本把 `双手五指完整` 写成了固定收尾句 —— 那是反效果的，已经删掉。**

它犯了两个错，而且两个都会主动制造它想避免的问题：

| 错 | 后果 |
|---|---|
| **① 它宣布了"画面里有一双手"** | 原本人物手插在口袋里、手在画面外、或者被身体挡住 —— **模型会硬造一双手出来** |
| **② "五指完整"是在念咒** | 越强调哪个部位，模型的注意力越集中在上面，**渲染时反而更容易崩** |

⭐ **判据：这句话是在「描述画面里有什么」，还是在「要求模型别画崩」？**
- ✅ 描述视觉事实 —— `她双手捧着杯子，掌心托着杯底`
- ⛔ 要求质量 —— `双手五指完整` / `手要画对` / `手指不要畸形`

⭐⭐ **更硬的一条判据：这句话能画出来吗？**
- **能画出具体的样子** → 有效（`掌心托住杯底，拇指扣在杯沿上` 画得出来）
- **画不出来，只是个"要求"** → 无效或反效果（`五指完整` 长什么样？画不出来 ——
  模型只能把它翻译成"把注意力集中到手上"，于是更容易崩）

⭐ **「手」这个字本身就是召唤。** 这是「名词自带的语义」定律的又一实例
（见 `03` 的名词定律）：**你写了"手"，模型就一定会安排一双手进画面。**

### 那手的质量怎么保证？（⚠️ 前提：这张图里本来就有手）

**靠"手在做什么"，不靠"手要完整"。**

| 做法 | 效果 |
|---|---|
| ✅ **写得具体**：`掌心托住杯底，拇指扣在杯沿上` | 模型有明确的目标姿态可依，比"五指完整"可靠得多 |
| ✅ **靠景别**：手占画面越大越可靠；手小或不在画面里，根本不用管 | 这是唯一的物理性保证 |
| ✅ **不想让手出现就不提手**：`她站在窗前，上身转向镜头` | 收尾句不宣布部位，模型就不会硬造 |
| ⛔ 加质量要求 / 反复强调 | 只会把注意力引过去 |

⛔ **这张表只在"手本来就该在画面里"时才用**（比如产品图里捧着杯子的手、弹琴的手）。
**画面里不需要手时，一个字都不要提** —— 提了就一定有。

⚠️ **这几条和「成对器官要钉数量和对称」不冲突** —— 那条是**描述光学事实**
（`两只眼睛里各有一小点一样大小的暖金色反光`），不是要求质量（`眼睛要对称`）。
**区别始终是：描述它长什么样 vs 要求它别崩。前者有效，后者反效果。**

### Detail Mode —— 按用途决定详略

**详略跟着"这张图干什么用"走，不跟着画面类型走。**
同一个题材，做草稿探索和做最终成品，该写的字数差一倍。

| Mode | 用在哪 | 行数 / 句数 | 说明 |
|---|---|---|---|
| **简洁 Concise** | 试方向、批量探索、改一个变量再看 | 1~2 句 | 只写"意图 + 主体 + 关键光/景"，其余留白 |
| **标准 Standard** | 默认档，绝大多数情况 | 5~8 句 / 150~300 字 | 骨架填满，细节只给关键项 |
| **详尽 Verbose** | 要发出去的成品、复杂场景 | 8~12 句 / 300~450 字 | 加材质、微纹理、空气介质 |
| **电影级 Cinematic** | 主视觉、封面、campaign 中心图 | 12 句以上 | 在详尽之上再叠"微观细节层"（见 05）|

⭐ **探索阶段一律用简洁档** —— 一次只动一个变量，简洁档才看得清是哪个变量起的作用。
**不要一上手就写详尽档**：出错了你不知道是哪句话造成的。

⚠️ 长度仍然是**控景别的主变量**：写超了画框会自己扩大。
削长度时按顺序砍：**用户没要的元素 → 场景描述 → 色彩 → 最后才动主体和服装**。

### 排除项：一律正向化，不写"不要 XX"

**规则只有一条：把"不要什么"改写成"要什么"，或者写成一句全局规格。**

| ⛔ 别写 | ✅ 改写成 |
|---|---|
| `不要投影` | `每个物体都直接贴在白纸上` |
| `不要有多余的人` | `画面里只有她一个人` |
| `不要文字、不要水印` | `画面里没有文字和水印`（这是**全局规格**，见硬规则 9）|

⭐⭐ **为什么正向化是唯一解，而不是"看模型下菜"**：

1. **文字召唤**。提示词里出现的名词，模型会当成"画面里要有的东西"。
   写 `不要紫色渐变` —— "紫色渐变"这个词本身就被召唤进来了。
2. **不需要按模型分档**。正向化在任何模型上都不会错，只是啰嗦一点；
   负向写法在不同模型上行为不一致，用户换个工具就翻车。
3. **"不要"的句式还会挤占预算**。同一句话改成正向描述，顺带把主体也讲清楚了。

⚠️ **唯一可以保留否定词的地方是「全局规格」** ——
`画面里只有[主体]` / `没有文字和水印`。这两句说的是**整张图的属性**，
不是"某个具体东西不要出现"，所以不构成召唤。

⭐ 排除项的现成写法在词库 `通用-背景收尾/排除项`：`scripts/lookup.py --group 排除项`

### 关于画质词

⛔ **不写** `masterpiece` / `8K` / `stunning` / `best quality` / `超高清` / `杰作` 这一类。

**它们不是"无效"，是"有害"** —— GPT-Image 一类模型带 anti-slop 倾向，
堆这些词会让结果**变差**（更塑料、更像素材库图）。这是实测结论，不是猜测。

⭐ 想要质感，**写具体的物象和光**，不要写形容词：
- ❌ `极致高清的皮肤质感` → ✅ `皮肤是哑光的，只有鼻尖和颧骨有一点高光`
- ❌ `大师级光影` → ✅ `左侧一扇窗，光从她右前方斜切进来`

### 关于镜头参数

⛔ **不写数字**（`50mm` / `f/2.8` / `ISO 400`）—— 写成**语感描述**：

| ⛔ 数字 | ✅ 语感 |
|---|---|
| `50mm` | `接近人眼所见的自然视感` |
| `85mm` | `长焦把背景压扁，人物从背景里浮出来` |
| `24mm` | `广角的透视拉伸，靠近镜头的东西被放大` |
| `f/1.4` | `景深很浅，背景全化开、光斑又大又圆` |
| `f/8` | `从前景到背景基本都清楚` |

⭐ 词库里 `通用-镜头构图/光圈` 与 `焦距` 两格已经把数字和它的**画面效果**写在一起了，
查 `scripts/lookup.py --group 光圈` 直接抄效果描述。

### 参数化模板 —— 一次出系列图时用

要出**同一套视觉、只换内容**的一组图（系列封面、角色多姿态、产品多角度）时，
**把变化项写成变量、其余锁死**。结构不变，模型得到的格式才一致。

```
场景：{地点，默认="蓝调时刻的里斯本小花店门口"}
主体：{人物，默认="穿藏青围裙的女性"}，{动作，默认="正在锁前门"}
关键细节：{光线}，{焦段感，默认="50mm 的观感"}，{主要材质}
用途：{用途，默认="杂志编辑类摄影"}
约束：{约束，默认="没有多余的招牌，背景里没有人"}
```

用法：**只改变量，不动结构**。一次改一个变量 —— 这同时也是"变量分离"的落地方式。

⭐ 简单版（三张以内）用不着模板，直接把变化项列出来给用户看：

> 这组我锁死：**蓝灰冷调 + 柔焦 + 半身构图 + 侧前窗光**。
> 只换三样：**场景**（书房 / 咖啡馆 / 雪原）、**服装**、**表情**。要不要这样出？

### 交付时标出 Assumptions

**用户没指定、你替他补的每一项，都要在交付里标出来。**
这是他一眼发现跑偏的第二道闸（第一道是"📷 这张图"那行）。

```
Assumptions（我补的，不对就说）：
· 画幅 3:4、半身 —— 你没说，按"亲密特写"默认
· 冷调蓝灰 —— 沿用你上次那组的调子
· 手写落款 —— 你没提，我按氛围图惯性加了，不要就删
```

### ⛔⛔ 只写「用户提过的 + 中性默认」，不写剧情

**这是"提示词太长"的真正根源** —— 不是形容词多，是你替用户拍了板。

| | 中性默认 ✅ 直接补 | 剧情化设定 ⛔ 要用户确认 |
|---|---|---|
| 定义 | 不写就出不来图的最少必要信息 | 给画面添加**剧情、情绪、关系叙事**的设定 |
| 人物 | "两个人站在画面中间，半身入镜" | "牵手一起望向雾的深处，肩挨着肩错开半个身位" |
| 服装 | "穿深色外套" | "宽松长外套 + 长及脚踝的连衣裙、裙摆被风吹起来" |
| 场景 | "背景是虚化的灰白色" | "脚下木栈道从近处收进雾里，两边湖水和天空连成两大块" |
| 判据 | **不写会不会崩？** 会 → 补 | **用户提过吗？** 没提过 → 不补 |

**自查：逐元素问"用户提过吗"。** 没提过的超过 **2 个** → 删到一个，或去问用户。

想补的时候**一次问完、一句话说完**：

> 我补了几个元素让画面成立：**湖边木栈道 + 清晨薄雾 + 逆光太阳**。
> 不想要就说一声，我把背景收成一片虚化。

### 画面里的文字：直接给内容 + 位置 + 形态

⛔⛔ **旧版这里写着"不要把文字内容写进提示词、建议后期叠字"—— 已经过时了。**
现在的模型（GPT-Image-2 / Seedream 4.5 / Nano Banana Pro / 即梦新版）**中英文字渲染已经很稳**。
**要字的图，就直接给字。**

⭐ **只要是海报 / 封面 / 产品图 / 信息图 / KV，默认就该问清文字内容，而不是劝用户放弃。**

### 三段式写法

```
文字：[确切内容]，[位置]，[字体形态 + 字号关系 + 颜色]
```

| 要素 | 怎么写 | ⛔ 不要 |
|---|---|---|
| **内容** | **用引号原样写出全部文字**，一个字都不改写 | 写个大意让模型自己发挥 |
| **位置** | `画面正上方` / `右下角` / `主体左侧三分之一处` —— 必须指定 | 不写位置（会压在主体上）|
| **层级** | 主标题大、副标题小，比例写清（`主标题字高约是副标题的两倍`）| 所有文字一样大 |
| **形态** | `粗黑体` / `纤细手写体` / `衬线宋体` / `等宽无衬线` | 只写"好看的字" |
| **颜色** | `深炭灰` / `米白` / 直接给色值 `#2C2C2A` | 不写颜色 |

### 示例

```
文字：画面正上方一行粗黑体主标题"秋日限定"，字高约占画面宽度的三分之一、深炭灰色；
主标题下方一行纤细无衬线副标题"2026 秋冬新品"，字高约为主标题的三分之一、同色；
两行文字居中，下方留出三分之一的空白放产品。
```

### 三条纪律

1. **要留白就同时写位置** —— `文字落在画面右三分之一，左侧留给主体`。
   ⛔ 只说"留白"不说在哪，模型不知道往哪留。
2. **文字和主体不要抢** —— 文字区域和主体区域要明确分开写。
3. **确认一下用户要的是"文字"还是"手写落款"** ——
   前者是设计元素（要清晰、要规范），后者是氛围配件（要随意、要轻）。

### 手写落款（氛围图 / 明信片 / 电影感海报）

这类是**氛围配件**，形态比内容重要：

| 要点 | 写法 |
|---|---|
| 形态 | `画面右上角有几行手写体中文小字，笔画细、力度轻，像随手写下的` |
| 位置 | 写明在哪一角（右上 / 左下 / 底部居中），⛔ 不写位置会飘到画面中间压住主体 |
| 留白 | 同时写 `留出周围的空白` —— 文字要落在空处，不能和主体抢 |
| 颜色 | 浅色字配暗背景，深色字配亮背景 |

⭐ 氛围图的手写落款**可以给内容也可以不给**：
给内容（`"冬与爱"`）能精确控制；不想定死内容就写 `几行看不清具体内容的手写小字`。
⚠️ 后者更容易被模型填成乱码，**要精确就写内容**。

### ⚠️ 什么时候仍然要提醒

只有一种情况：**文字量很大**（整段说明文字、信息图表里十几行字）。
这时候**分两批做**：先出图，再把文字用设计工具叠上去 ——
**不是因为模型写不好字，是因为排版精度不够**。少量文字直接写死就行。

### 删掉这三类词

| 类别 | 例子 | 为什么删 |
|---|---|---|
| **装饰性形容词** | 唯美的 / 高级的 / 精美的 / 令人震撼的 | 不指向可画的东西，模型读不懂 |
| **重复描述** | "色彩鲜艳"+"高饱和度" ／ "清晰"+"细节丰富" | 说的是同一件事 |
| **模型自带先验** | 写了"一张真实照片"又写"真实感""写实风格" | 冗余 |

### 标准段落模板

```
[意图 / 用途]。                       ← 为自媒体封面做的一张 3:4 竖幅人像照片。
[画幅比例 + 景别]。                    ← 从腰往上入镜，人物占画面中段，能看清脸。
[场景 + 光源位置]。                    ← 她站在一条雨夜巷道里，正前方偏下一台冷白灯箱……
[主体 + 关键特征 + 动作 + 服装道具]。   ← 一个年轻女性，黑色短发被雨打湿贴在脸侧……
[关系 + 视线]（画面里两个人以上才写）。  ← 她侧过脸看着他，两个人额头几乎碰在一起，都没看镜头。
                                        ⛔ 不要写成"两人的额头几乎碰在一起"—— 性别会丢
[光的落点 + 阴影]。                    ← 冷白光从下往上打亮下颌和鼻梁，另半张脸落在暗部里。
[主色 + 第二个色温在哪]。              ← 整体青蓝冷调，唯一的暖色是右后方那块霓虹灯牌。
[介质 + 质感 + 细节]。                 ← 雨丝被灯光照成一条条亮线，地面把霓虹拉成长反光带。
[文字]（要文字就写，不要就跳过）。      ← 画面正上方一行粗黑体主标题"秋日限定"……
[收尾]。                              ← 画面里只有她一个人，没有文字和水印。
```

⛔ **顺序不能换**：**意图打头**（开头的词会选中模型的"模式"）、**场景写在主体之前**、
**画幅和景别相邻**、**关系紧跟在主体之后**（迟了会被后面的描述盖掉）。
依据见 `01` 的「装配顺序」一节。

⭐ **两个例外**（这类图的槽位要"换掉"不是"填上"，见 `01` 的「特殊画面类型」）：

| 类型 | 怎么变 |
|---|---|
| **人物设定（四视图）** | 「场景」槽 → 换成**四格排布 + 共用纯色背景**；「光照」→ 均匀平光；末尾加**逐条钉死的特征清单** |
| **绘画形式类**（水墨 / 工笔 / 版画）| 「光照」槽 → 换成**墨色的层次分布**（焦浓重淡清）|

## 只有中文一种形态

| 情况 | 做法 |
|---|---|
| 任何情况 | **中文整段自然语言**，没有例外 |
| 用户点名某个工具的专属语法 | ⛔ 不加参数尾、不写逗号词组链。告诉他"这条中文描述在任何工具里都能用" |
| 用户在做英文平台内容 / 主动要英文 | ✅ 给他中文稿，另附一份英文**整段自然语言**（不是词组链） |
| 用户要中英对照 | 中文整段 + 英文整段，**两段语义一一对应** |

⭐ **需要查某个词的英文时**，用 `scripts/lookup.py --kw <中文词>` ——
那是**检索与对照**用途，⛔ 不是让你把整条提示词写成英文。

⛔ **要给英文时不要逐字直译** —— 中英的摄影术语不对称。
"逆光"对应 `backlight`，"发丝光"要写 `rim light on hair strands`，
直译成 `hair silk light` 模型读不懂。
